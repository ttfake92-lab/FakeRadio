## 代码审查发现

### P1 - active brief 展示和控制对象不一致

`apps/web/src/features/player/skin-stage.tsx` 已按 `activeBriefId` 计算展示层的 `activePlan` / `activeJob`，但 `GenerationConsole` 的控制回调来自 `PlayerShell`。

`apps/web/src/features/player/player-shell.tsx` 中：

- `activePlan = productionPlans.find((p) => p.active) ?? null`
- `activeJob = productionJobs.find(active) ?? productionJobs[0] ?? null`
- `handlePauseJob` / `handleResumeJob` / `handleCancelJob` / `handleAddConstraint` 都使用这些未按 `activeBriefId` 过滤的对象

风险：当前 UI 展示 brief B 的 job 状态，但点击暂停、取消或追加约束时，实际操作 brief A 的 job/plan。

已创建：`.scratch/fakeradio-show-production/issues/14-active-brief-ui-control-and-browser-gate.md`

### P1 - Production Board export project 可能跨 brief

`apps/web/src/features/show/production-board.tsx` 中：

- `completedJob = jobs?.find((j) => j.status === "completed")`
- `activeProject` 从全量 `projects` 中按 `completedJob.activeJobId` 或 `completedJob.briefId` 选择

而 `SkinStage` 传入 ProductionBoard 的 `jobs` / `projects` 是全量列表。结果是 active brief 的 Production Board 可能导出、删除或展示另一个 brief 的 project。

已并入 Issue 14。

### P2 - 覆盖缺口仍存在

Issue 13 文档中曾把多 brief query filter 和前端 active brief 切换覆盖列为待后续，但状态文件又声明“多 brief 用户流不串台（已通过集成测试验证）”。本轮代码审查发现仍有 UI handler/project 选择漂移，说明该覆盖缺口不应标为完成。

已写回 `AUTOMATION_STATE.md` 的 Blockers 和 Next Action。
