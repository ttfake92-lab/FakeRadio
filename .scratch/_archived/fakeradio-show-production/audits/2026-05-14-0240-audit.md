## 代码审查发现

### P1: `/api/plans?briefId=` 和 `/api/jobs?briefId=` 前后端 contract 漂移

证据：

- `apps/web/src/lib/api-client.ts` 的 `getShowPlans(briefId)` 请求 `/api/plans?briefId=...`。
- `apps/web/src/lib/api-client.ts` 的 `getShowJobs(briefId)` 请求 `/api/jobs?briefId=...`。
- `server/src/http/register-routes.ts` 的 `GET /api/plans` 忽略 query，直接 `showPlanRepo.list()`。
- `server/src/http/register-routes.ts` 的 `GET /api/jobs` 忽略 query，直接 `jobRegistry.list()`。

影响：

- 前端按 brief 加载 Production Board / Generation Console 时可能拿到全局所有 plans/jobs。
- `SkinStage` 用 `productionPlans.find((p) => p.active)` 和第一个 active job，会在多节目、多 brief 场景下串台。
- Show Production 的 “show -> block -> episode” board 可能展示另一期节目的 plan/job。

实现 agent 下一步应统一 contract：要么 server 支持 query filter，要么前端改用已存在的 path route；推荐 server 支持 query filter，以匹配当前 api-client 语义。

### P1: `generateFromPlan()` 创建新 `ShowPlan.id`，导致旧 active 版本不会失活

证据：

- `server/src/show/show-plan-generator.ts` 的 `generateFromPlan()` 返回 `id: plan-${randomUUID()}`。
- `server/src/show/show-plan-repository.ts` 只执行 `UPDATE show_plans SET active = 0 WHERE id = ?`。

影响：

- 追加约束后会得到另一个全新的 plan id，而不是同一 plan 的新 version。
- 旧 plan 仍保持 active；`list({ briefId, activeOnly: true })` 可能返回多个 active plan。
- `executeScheduledJob()` 使用 `plans[0]`，调度和 Generate now 可能执行旧版本或不确定版本。

实现 agent 下一步应让新版本沿用同一个 `ShowPlan.id`，仅递增 `version`；保存新 active version 时，同一 plan id 下旧版本必须失活。必要时补充按 brief 只有一个 active plan 的约束或验证。

### P2: `generate-now` 的 adapter fallback 与 scheduler 路径不一致

证据：

- `server/src/http/register-routes.ts` 中 `generate-now` 传入 `publicMetadataAdapter ?? webResearchAdapter ?? createMockStorySourceAdapter()` 和对称的 web fallback。
- `server/src/http/create-server.ts` 中 scheduler execution deps 直接传 `options.publicMetadataAdapter` 和 `options.webResearchAdapter ? cached : undefined`。

影响：

- `generate-now` 默认会聚合 storySource + public mock + web mock 三层来源。
- scheduler 默认只使用 storySource。
- 两条路径虽调用同一个 `executeScheduledJob()`，但默认资料来源语义不一致，trace 和口播类型可能不同。

实现 agent 下一步应明确默认策略：本地无真实 provider 时禁用 public/web 还是使用 mock；两条入口必须一致，并在 trace 中记录 disabled/mock fallback 摘要。

### P2: 浏览器验收仍是未关闭的 HITL blocker

证据：

- 当前 `AUTOMATION_STATE.md` 已写明 320px/375px/1440px 浏览器验收需要用户本地完成。
- Issue 07 和 Issue 11 仍依赖浏览器验收确认 Production Board 折叠、Generation Console 控制按钮、Export Queue 下载入口。

影响：

- Phase 4 / UI 完成声明不能只靠 typecheck 或 HTTP 测试关闭。

实现 agent 下一步应先修 dev server 可启动阻断，或把本地用户需要执行的浏览器验收 checklist 写清楚，并保持 HITL blocker 不关闭。
