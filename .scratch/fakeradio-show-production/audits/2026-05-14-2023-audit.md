## 代码审查发现

### P1 - `Schedule tonight` 的 HTTP 主入口绕过了 Daily Show plan generator

`server/src/http/register-routes.ts` 的 `/api/shows/schedule-tonight` 在 brief 没有 active plan 时仍调用通用 `showPlanGenerator.generate(brief)`。该 generator 生成的是 Theme Story Show 的 `opening/origin/signature-era/closing` 等故事 block，不会生成 Daily Show 的 `morning/afternoon/evening` 时间段 block。

这使当前 slice 3 的实现只覆盖了 `scheduleTonightBriefIfNeeded()` 被直接调用、且 brief 没有 active plan 的内部路径；但真实用户流是：

1. 用户通过 `/api/shows/schedule-tonight` 调度节目。
2. route 先创建 active plan。
3. 夜间 scheduler 发现已有 active plan，于是不会触发 `dailyShowPlanGenerator.generate()`。

影响：

- `daily-show` 经 HTTP `Schedule tonight` 后可能拿到 Theme Story Show plan。
- P2-02 “Daily Show 全天节目池语义”未真正进入用户主链路。
- 后续 slice 4 即使把 `DailySelectionEngine` 注入 `executeScheduledJob`，也会在错误的 block 结构上执行。

建议实现顺序：

1. 在 `/api/shows/schedule-tonight` 和必要的 `/api/shows/generate-now` 中按 `brief.type === "daily-show"` 选择 `DailyShowPlanGenerator`。
2. 增加 HTTP 级测试：daily-show 走 `/api/shows/schedule-tonight` 后，`GET /api/plans?briefId=...` 只返回 `morning/afternoon/evening` roles。
3. 再进入 slice 4：把 `DailySelectionEngine` / `StateRecentPlayedRepository` 注入 scheduler execution path。

### P2 - active issue 的完成清单与真实实现边界不一致

`.scratch/fakeradio-show-production/issues/p2-02-daily-show-recent-play-exclusion.md` 已把 “Scheduler 集成”记为 done，但没有记录 HTTP `Schedule tonight` 主入口仍会预先创建通用 theme plan。当前 issue 的下一步不能只写 “Daily SelectionEngine 在 scheduler 执行路径中实际使用”，需要先补上 route plan-generator 分流门禁，否则 Daily Show 真实链路仍不对齐 PRD。
