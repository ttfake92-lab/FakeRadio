## 代码审查发现

### P0: 前端项目列表 API 与 server route 漂移

位置：

- `apps/web/src/lib/api-client.ts:164`
- `server/src/http/register-routes.ts:652`

`getShowProjects()` 请求 `/api/projects`，但 server 只有 `GET /api/shows` 返回 `ShowProjectsListResponseSchema`。这会让 `PlayerShell` 的 `productionProjects` 始终为空，Production Board 找不到 completed project，Export Queue 也无法用真实 `ShowProject.id`。当前 HTTP 测试覆盖了 server route，但没有覆盖 web api-client 与 server contract 的组合。

纠偏：要么 server 增加兼容 `GET /api/projects`，要么前端改为调用 `/api/shows`；同时补一个 contract / api-client 测试，防止 route 再漂移。

### P0: Export Queue 仍可能用 `planId` 当 `projectId`

位置：`apps/web/src/features/player/skin-stage.tsx:237`

当 `productionProjects` 为空或找不到匹配 project 时，`projectId` 退回 `job.planId`。结合上面的 `/api/projects` 漂移，这条 fallback 会在完成 job 后把 plan id 发到 `/api/export/project/:id/download`，造成 404 或错误下载状态。

纠偏：没有真实 `ShowProject.id` 时不要生成可下载 task；显示“等待项目同步”或隐藏下载按钮。

### P0: Export Package 仍会写 0 字节 `show.mp3`

位置：`server/src/export/export-show-project.ts:89`、`server/src/export/export-show-project.ts:177`、`server/src/export/export-show-project.ts:181`

当前没有有效音频输入、没有 episode、或 ffmpeg fallback 找不到本地文件时，会写 `Buffer.alloc(0)`。这会让 export route 返回 200，并让下载列表看起来完整，但 `show.mp3` 不可回听，不满足 PRD 的本地节目工程包验收。

纠偏：没有可拼接音频时应 fail fast 并返回可诊断错误；或者明确产出真实可播放音频。不能用空文件代表成功。

### P1: Generation Console 控制按钮仍是空操作 fallback

位置：`apps/web/src/features/player/skin-stage.tsx:318`

`onPause/onCancel/onAddConstraint` 仍用 `(() => {})` 补齐。`GenerationConsole` 只看 prop 是否存在决定展示按钮，所以没有 active job 或当前状态不支持动作时仍可能展示可点击但无效果的控制。

纠偏：只在 active job status 支持且真实 callback 存在时传 prop。`running` 才能 pause/cancel/add constraint，`paused`/`needs-replan` 才能 resume/cancel，completed/failed/cancelled 不展示操作按钮。

### P1: Scheduler execution 仍绕过 typed boundary

位置：`server/src/http/create-server.ts:226`

`create-server.ts` 仍用 `as any` 传入 `SchedulerExecutionDeps`。这会隐藏 adapter contract 漂移，也是本地 server orchestration 边界没有完全收敛的信号。

纠偏：抽出 typed show production executor，`generate-now` 与 scheduler 都调用同一服务；不要在 `create-server.ts` 里用 `as any` 拼依赖。

### P1: Trace 导出仍只看 job trace，没有合并 ShowProject trace

位置：

- `server/src/http/register-routes.ts:714`
- `server/src/export/export-show-project.ts:184`

`generate-now` 写了 ShowProject trace 的 `job-started`，episode execution 写 job trace。导出时只在 `job.trace.length > 0` 时重写 `production-trace.jsonl`，没有明确合并 ShowProject trace 与 job trace，也没有在这一层验证 redaction 策略。

纠偏：导出时读取已有 ShowProject trace，合并 job trace 的摘要级条目，按固定 schema 写入，并验证不包含密钥、cookie、完整 system prompt 或私人记忆原文。

### P2: P2-01 状态声明过早

位置：`.scratch/fakeradio-show-production/AUTOMATION_STATE.md`

状态文件原本宣称 P2-01 已验证通过，但 active issue 自身仍写着 `Status: ready-for-agent` 且 acceptance criteria 未关闭。当前 scheduler 也仍受 typed orchestration、trace、export、browser 验收阻塞。

纠偏：P2-01 不能作为完成项继续推进。先关 issue 10，再回到 P2 scheduler 验收。
