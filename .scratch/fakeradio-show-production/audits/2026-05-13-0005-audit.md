## 代码审查发现

### P1: 最新 P2 集成仍建立在不可信日志/trace 上

位置：`server/src/show/scheduler-integration.ts:25-41`

实现任务在本轮审计过程中新增了 `scheduleTonightBriefIfNeeded()` 并集成到 `create-server.ts`。该函数会 `create` job、调用 `addLog()`、`start()`、再次 `addLog()`，然后把 brief 更新为 `generating`。但由于 `addLog()` 的落库问题尚未修复，scheduler 生成的制作日志不会可靠保存；而且它只把 job 启动到 `running`，没有执行 episode 生成、写 ShowProject trace 或完成 Export Package 所需产物。

这进一步确认：不能把 P2-1 标为“常驻 server 读取 Brief 并执行生成 job”完成，只能算“创建并启动 job”部分完成。

### P1: Generation Console 和导出 trace 可能为空

位置：`server/src/show/show-generation-job.ts:134-140`、`server/src/show/show-generation-job.ts:244-258`

`updateJob()` 在 `updated.status === job.status` 时直接返回 `null`，不会执行 `stmtUpdate`。`addLog()` 和 `addTrace()` 只更新 `logs` / `trace` / `updatedAt`，不会改变 `status`，所以日志和 trace 实际不会落库。

### P1: Production Board 导出调用传错 ID

位置：`apps/web/src/features/show/production-board.tsx:24-32`、`apps/web/src/lib/api-client.ts:171-181`、`server/src/http/register-routes.ts:457-463`

前端 `handleExport()` 调用 `exportProject(completedJob.planId, ...)`，但后端路由是 `POST /api/projects/:id/export`，需要的是 `ShowProject.id`。

### P1: Export Package 不满足 `show.mp3` 验收

位置：`server/src/export/export-show-project.ts:64-89`、`server/src/http/register-routes.ts:502-506`

当前导出只写 `show-plan.json`、`show-notes.md`，并在存在 job trace 时写 `production-trace.jsonl`。没有生成或暴露 `show.mp3`，下载白名单也没有 `show.mp3`。

### P2: show notes episode 收集路径绕过 ShowProject

位置：`server/src/export/export-show-project.ts:20-31`

`collectEpisodeTracks()` 根据 `plan.briefSnapshot.targetDate` 读取 `user/shows/<targetDate>/episode-*.json`，而不是从 `project.directoryPath` 或 ShowProject 索引读取。

### P2: P2-1 issue 规格引用了不存在的 `JobRegistry.execute`

位置：`.scratch/fakeradio-show-production/issues/p2-01-scheduler-consume-scheduled-brief.md:38-50`

当前 `JobRegistry` 只有 `create/start/pause/resume/complete/fail/cancel/markNeedsReplan/addLog/addTrace`，没有 `execute`。P2-1 应在 server orchestration 层消费 scheduled Brief，`createPrewarmScheduler` 继续只负责时间触发。
