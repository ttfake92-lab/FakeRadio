## 代码审查发现

### P0: `Generate now` 没有执行生成，只创建 running job

位置：`server/src/http/register-routes.ts:663-722`

`POST /api/shows/generate-now` 当前只创建或更新 ShowProject、保存 ShowPlan、创建 job、调用 `jobRegistry.start()`，然后返回 `status: running`。它没有调用 `executeScheduledJob` 或任何 episode execution 服务，因此不会生成 episode 文件、不会完成 job、不会让 Export Package 进入可导出状态。

这直接否定 Phase 1 “Generate now -> 生成日志 -> Production Board -> Export Package”已完成的状态声明。

### P0: Export Package 用 0 字节 `show.mp3` 占位

位置：`server/src/export/export-show-project.ts:79-89`

当前没有 `project.showAudioPath` 时会写入 `Buffer.alloc(0)` 到 `show.mp3`。这会让下载列表看起来满足合同，但产物不可回听。PRD 的本地节目工程包必须可用于个人本地回听，空文件不能作为验收通过。

### P1: Scheduler execution 不是 `generate-now` 复用路径，且绕过类型边界

位置：`server/src/show/scheduler-integration.ts:42-257`、`server/src/http/create-server.ts:218-243`

夜间调度新增了独立的 `executeScheduledJob()`，而 `generate-now` 没有复用它。`create-server.ts` 还用 `as any` 注入执行依赖。这会造成两套生成路径漂移，并隐藏 adapter 类型错误。

### P1: Trace 导出不稳定，且来源不统一

位置：`server/src/export/export-show-project.ts:91-100`

includeTrace=true 时只写 `job.trace`。但 `generate-now` 写的是 ShowProject trace 文件，scheduler execution 写的是 job trace。若 job.trace 为空，导出包不会包含 `production-trace.jsonl`。应该合并 ShowProject trace 与 job trace 的摘要级信息，并做隐私 redaction。

### P1: Generation Console 可能展示空操作按钮

位置：`apps/web/src/features/player/skin-stage.tsx:307-320`、`apps/web/src/features/show/generation-console.tsx:189-237`

`SkinStage` 给 `onPause/onCancel/onAddConstraint` 传入空函数 fallback，`GenerationConsole` 只要 prop 存在就展示按钮。没有 active job 或 job 不支持某动作时，用户仍可能看到可点击但无效果的控制按钮。按钮状态应由 job status 驱动，而不是用空函数填充。

### P2: ExportQueue 仍有 project id fallback 风险

位置：`apps/web/src/features/player/skin-stage.tsx:237-246`

Export task 找不到 ShowProject 时仍 fallback 到 `job.planId`。这会把旧的“planId 当 projectId”问题延伸到 ExportQueue 下载路径。没有真实 project 时应隐藏下载或显示不可导出状态，不应发错 ID。

### P2: Issue tracker 与状态文件漂移

位置：`.scratch/fakeradio-show-production/issues/02-*.md`、`03-*.md`、`04-*.md`、`07-*.md`、`08-*.md`、`AUTOMATION_STATE.md`

`AUTOMATION_STATE.md` 宣称 Phase 1/2 完成，但多个早期 issue 仍是 `needs-triage`，acceptance checklist 未同步关闭。下一轮在修回归前不必整理所有历史状态，但不能继续用“所有验收完成”作为前提。
