# FakeRadio Player 信息架构重排设计：9:16 On Air 终端

## 背景

FakeRadio 前端不应继续按传统音乐播放器来组织。当前目标是把首页从“功能平铺的播放器面板”重排为一个由 LLM 驱动的个人电台界面。

默认常驻页不是普通网页比例，也不是完整播放器控件页，而是一个适合手机打开、也适合在桌面置顶浮动的小型电台终端。默认比例为 `9:16`，默认主题按参考图复刻为终端、点阵、深色电台直播间风格。

## 设计目标

- 默认首页是 `On Air`，表达“电台正在发生什么”，而不是“播放器有哪些控件”。
- 默认主题先一比一复刻参考图的布局、比例、密度和视觉层级。
- 播放控件保留但降级为窄播放带，不主导界面。
- AI DJ 文本和用户对 DJ 的指令输入成为核心交互。
- 功能拆成页面模式，不把所有功能塞进一个默认页。
- 9:16 比例必须自适应手机、桌面和置顶浮窗场景。

## 非目标

- 本阶段不重新设计全部页面。
- 本阶段不接入新的外部 provider。
- 本阶段不做完整主题商店或主题编辑器。
- 本阶段不把网易云登录、诊断详情、故事来源详情、品味编辑全部塞进 `On Air`。
- 本阶段不追求传统播放器的完整控件体系。

## 默认页面：On Air

`On Air` 是默认常驻页，按参考图复刻结构，内容替换为 FakeRadio 语境。

页面自上而下分为：

1. 顶部品牌栏
   - 左侧：头像或电台圆形标识 + `FakeRadio` 点阵风格字标。
   - 右侧：`LOGIN`、`DARK`、`LIGHT` 等主题/状态入口。默认可以保留视觉占位，后续再接真实逻辑。

2. 大号时间区
   - 中央大号点阵时间，例如 `21:11`。
   - 时间下方显示星期、日期和 `ON AIR`。
   - 可显示当前模式，例如 `Focus`、`Night`、`Morning`。
   - 这是页面主视觉，替代传统播放器的 album art。

3. 窄播放带
   - 左侧显示当前曲目：标题、艺术家、播放状态。
   - 中间或右侧显示少量控制：上一段、暂停/播放、下一段、收藏。
   - 底部是进度条和当前/总时长。
   - 控件数量保持克制，视觉上不能压过时间区和 DJ 区。

4. Queue 黑条
   - 显示 `QUEUE` 和当前队列数量。
   - 默认常驻但低信息密度。
   - 点击后可进入队列或展开抽屉，默认页不直接展示完整队列。

5. AI DJ 直播区
   - 顶部显示 `FakeRadio` / `AI DJ` 和 `LIVE`。
   - 显示连接状态，例如 `Connected to FakeRadio server`。
   - 主体是 DJ 文本气泡，承载 LLM 生成的解释、故事、当前模式说明或下一段意图。
   - 气泡下方显示时间戳和 `REPLAY`。
   - 底部可显示 `Now playing: title · artist`。

6. 底部输入区
   - 文案为 `Say something to the DJ...` 或中文等价文案。
   - 输入不是普通聊天优先，而是给 DJ 发指令，例如“更安静一点”“继续这个氛围”“少一点人声”。
   - 保留语音按钮和发送按钮的位置。

7. 底部状态栏
   - 左侧：`FAKERADIO FM`。
   - 右侧：`CONNECTED`。

## 页面模式

默认页只承载 `On Air`。其他能力作为独立页面或二级入口存在：

- `Modes`：切换场景模式，例如写代码、晨间启动、夜间降速、阅读、散步、自定义 mood。
- `Memory`：品味、近期反馈、收藏、跳过原因、今天不想听什么。
- `Signals`：故事来源、provider 健康、fallback、候选来源、重排来源和其他诊断。
- `Setup`：网易云登录、Cookie、API key、adapter 配置。默认可作为 `Signals` 或更多菜单下的二级入口。

主导航可先按 `On Air / Modes / Memory / Signals` 组织。`Setup` 不作为日常常驻主入口。

## 主题套装

本阶段至少需要落地两个主题套装：

- `Terminal FM`：默认主题，按参考图复刻 AI DJ 终端。
- `Morning Console`：晨间启动主题，暖色低刺激，适合早晨打开手机或桌面浮窗。

两个主题共享同一套 `9:16 On Air` 信息架构和页面分区，不改变顶部品牌栏、大号时间区、窄播放带、Queue 黑条、AI DJ 直播区、底部输入区和底部状态栏的结构。主题差异通过背景系统、色彩、字体气质、状态徽章、DJ 消息样式、控件语言、动效节奏和文案语气表达。

### 默认主题：Terminal FM

默认主题名称为 `Terminal FM`。它是 FakeRadio 的默认品牌皮肤。

主题特征：

- 深色终端底色。
- 点阵网格背景。
- 像素或点阵感字标和大号时间。
- 青绿色 `ON AIR` / `LIVE` 状态色。
- 播放区、队列区和 DJ 区用横向电台控制台层级分隔。
- DJ 文本气泡高对比、类似直播间文字块。
- 交互按钮小而克制，避免传统播放器占据视觉中心。

后续主题套装不只是换色，而应成套定义：

- 背景系统。
- 字体气质。
- 状态徽章。
- DJ 消息样式。
- 控件语言。
- 动效节奏。
- 空状态和系统文案。

### 必需主题：Morning Console

`Morning Console` 是首批必需主题，不是远期候选。它用于晨间启动、低刺激唤醒和轻量进入专注状态。

主题特征：

- 保留终端骨架和 `9:16` 分区，但视觉温度更高。
- 背景从深色终端改为暖色低对比，例如晨光米色、柔和琥珀、低饱和青绿。
- 点阵背景仍保留，但对比度降低，避免早晨打开时刺激过强。
- `ON AIR` / `LIVE` 状态色可以从高亮青绿色调整为柔和薄荷绿或暖白绿。
- 大号时间仍是主视觉，但字重和发光效果比 `Terminal FM` 更轻。
- DJ 文本语气更短、更柔和，偏“启动”和“陪伴”，避免过度解释。
- 控件视觉更安静，默认强调“开始这一段”而不是密集控制。

后续可规划主题：

- `Night Signal`：夜间降速，更暗、更低对比、更像深夜信号台。
- `Paper Log`：电台日志，适合阅读故事与来源。

## 9:16 自适应比例

默认设计单位是一个锁定 `aspect-ratio: 9 / 16` 的终端面板。

比例策略：

- 桌面端：页面可以是普通网页背景，但核心 `On Air` 面板必须保持 `9:16`。面板优先根据可用高度计算宽度，避免超出视口底部。
- 手机端：面板优先根据可用宽度计算高度，接近全屏，但保留安全边距。
- 浮窗端：面板保持 `9:16`，允许整体缩放，但不能被拉伸成普通网页比例。
- 内容溢出时，优先压缩区块间距和局部滚动 DJ 区，不能改变外层比例。
- 输入区和底部状态栏必须始终可见。

建议实现约束：

```css
.on-air-stage {
  min-height: 100svh;
  display: grid;
  place-items: center;
}

.on-air-panel {
  aspect-ratio: 9 / 16;
  width: min(
    calc(100vw - 24px),
    calc((100svh - 24px) * 9 / 16),
    430px
  );
  max-height: calc(100svh - 24px);
}
```

字体和间距不应只依赖 viewport 宽度。实现时优先使用面板级 CSS 变量、容器查询或少量断点，保证不同容器尺寸下信息仍在固定比例内成立。

## 数据映射

现有前端状态可映射到新结构：

- `now.track` / `playback.episodeData.track` → 窄播放带当前曲目。
- `playback.episodeStateLabel` / `playbackLabel` → 播放状态或顶部状态。
- `streamStatus.label` / `streamStatus.detail` → 底部连接状态或 `Signals`。
- `musicStatus` → 默认页只在异常时提示；正常状态进入 `Signals`。
- `now.dj.say` / `playback.episodeData.story.text` → AI DJ 文本气泡。
- `now.queue` → Queue 黑条和二级队列视图。
- `taste` / `plan` → `Modes` 或 `Memory` 页面，不在默认页平铺。
- `nextResult.diagnostics` → `Signals` 页面，不在默认页平铺。
- `neteaseLogin` / `neteaseQr` / cookie 注入 → `Setup` 页面。

## 错误与异常

- 本地 server 断开时，底部状态从 `CONNECTED` 改为异常状态，并在 DJ 区显示连接提示。
- music provider 回退到 mock 时，默认页只显示一个低干扰异常徽章；详细解释进入 `Signals`。
- story audio 失败时，保留现有错误语义，DJ 区显示“口播加载失败”。
- 预取失败不占用默认页主视觉，只影响 Queue 或 Signals。

## 测试与验证

实现时需要验证：

- `9:16` 面板在手机竖屏、桌面窗口和窄浮窗下比例稳定。
- 底部输入区始终可见。
- 大号时间、播放带、Queue、DJ 区和输入区不会互相挤压重叠。
- 文本过长时 DJ 气泡可局部滚动或截断，不破坏外层比例。
- mock provider、断线、story audio 错误等状态能显示在正确层级。
- 现有 `player-view-model` 的中文标签测试继续通过。

## 实施边界

本设计只要求重排 `apps/web` 的 Player 信息架构和默认主题，不改变 server orchestration、adapter 或 shared contract。前端仍只调用本地 server，不直接访问外部 provider。
